2. How to make a submission into the contest

  1. Get the data (DrivenData login required — verified redirect to login; cannot auto-download here): https://www.drivendata.org/competitions/306/competition-doe-gems/data/. Place training_features.tif, labels.tif, sample_submission.tif into data/.
  2. Prepare the stack: python scripts/prepare_data.py
  3. Generate + align: python scripts/generate_submission.py then python scripts/align_to_competition_grid.py --reference data/sample_submission.tif
  4. Write + validate (format receipt): python scripts/submission_writer.py --reference data/sample_submission.tif
  5. Run all gates: python scripts/validate_submission.py → verdict promote / negative
  6. Upload via the DrivenData submission page (single .tif or .zip, note ≤140 chars), within the weekly cap.

Fix for "Predicted values must be in range [0, 1]"

The portal rejects values outside [0, 1] or NaN. The pipeline guarantees: np.clip(prediction, 0, 1), replace non-finite with 0 (-zeros encoding), single-band float32, finite everywhere, no NaN inside the footprint.

4. Why GEMSDOE32 scored 0.2778 (PhD synthesis) & how to beat it

Metric: DTI = Tversky index, α = 0.2, β = 0.8, 300 m triangular kernel. β (0.8) > α (0.2) → false positives penalised 4× false negatives → sparse, confident dots win.

Why 0.2778: every focus-9 leader re-thins the H19-5 ridge skeleton — d = 2.8 dotting cut false positives ~3× (+0.0678); B2 excised 6,436 near-catalogue detector-echo dots (+0.0178). H19-5 covers only ~30–36% of hidden faults → re-thinning asymptotes below ~0.295.

To surpass 0.2778 toward public leaders (0.3195 / 0.4413 / 0.4437): close the 1 m LiDAR gap with 10 m 3DEP; detect blind range-front uplift via fluvial χ / ksn + hydrothermal upflow; Stage-2 spatial context (+0.008895 measured); add off-catalogue pre-Quaternary faults + ASTER TIR alteration.
