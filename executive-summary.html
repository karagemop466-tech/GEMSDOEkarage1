The checks are designed to fail closed automatically. A missing result is not a request for a human inspector to guess whether a file is good enough.

The required sequence

  1. Method and data. Identify the assigned parallel lane and shared template; restore pinned features, official grid, footprint and whole fault segments.
  2. Leakage control. Withhold whole segments with a buffer. Derive catalogue features from visible faults only. Run single-feature canaries; investigate any AUC above 0.90.
  3. Surface uniqueness. Compare against the complete registry before placing dots. Stop if rank-correlation exceeds 0.90 or the specified proximity rule fails.
  4. Holdout improvement. Use the shared pooled-DTI evaluator, alpha 0.2, beta 0.8, 300 m triangular kernel. Record evaluator version, withheld positives and 95% CI; compare to the same-fold current best.
  5. Final uniqueness. Stop if more than 70% of candidate dots fall within 3 px of any registry mask. Different SHA hashes do not prove different predictions.
  6. Saved-byte validation. Use the shared writer. Reopen the TIFF and require one band, finite [0,1] values and exact template CRS, shape and transform. Our conservative validator also rejects NaN outside the footprint.
  7. Separate selector. Only after all evidence passes, check the actual weekly allowance and authorize a slot. This project does not auto-submit.

When a candidate is cleared

A future release must show a unique filename, SHA-256, download link, validation report, holdout evidence and a note of at most 140 characters. Download the .tif (not this HTML page or a JSON report), choose it in the official submission form, paste the note, and retain the receipt linked to the file hash. A ZIP must contain exactly one TIFF.

These are instructions for a future cleared artifact, not authorization to upload any historical file linked here.

About “Predicted values must be in range [0,1]”

Potential causes include negative nodata sentinels, infinity, NaN handling or predictions outside the interval. The original failed file was not supplied, so its cause cannot be diagnosed. Do not blindly clip bad inputs: first inspect prediction generation, footprint and nodata handling, then validate the saved bytes. Format success alone does not prove portal acceptance or competitive performance.
