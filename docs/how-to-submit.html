FOUR STEPS

Submission steps (when a file is cleared)

01 / EVIDENCE

Pass the automated gates

Use the shared evaluator (vendor/gems57/evaluate_holdout.py) with buffered whole-segment hide-and-recover holdout. Derive every catalogue-based feature only from visible faults. Mask visible faults pixel-exactly. Score pooled DTI (α=0.2, β=0.8, 300 m triangular kernel). Test each feature alone for leakage — single-feature AUC above 0.90 means leakage. Beat the frozen comparable holdout best before any slot is considered.

02 / UNIQUENESS

Check against the registry

Compare the candidate surface and dots against every registry raster: rank correlation must not exceed 0.90, and no more than 70% of candidate dots may fall within 3 px of any one registry raster's dots. Log any drift as a duplicate and stop. A unique filename does not imply a unique submission.

03 / FORMAT

Validate the GeoTIFF

Reopen the saved TIFF and verify: single band, float32, values finite and in [0,1], no NaN inside the footprint, CRS = EPSG:32611, shape = 3730×3292, transform = (100, 0, 243350, 0, −100, 4508550), no positive mass outside the valid footprint. The portal rejects values outside [0,1]. Local validation is not organizer acceptance.

04 / DOWNLOAD + UPLOAD

Get the file and submit

Download the approved single-band GeoTIFF (or a ZIP containing one GeoTIFF). Check its SHA-256, unique submission name (1–140 chars) and note (≤140 characters). Open DrivenData, select Submit → Make new submission, choose the .tif or ZIP, paste the note, and retain the file-linked organizer receipt as ORGANIZER-CONFIRMED evidence. Maximum three submissions per week.
