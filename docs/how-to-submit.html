SUBMISSION OVERVIEW

What to submit

A single-band GeoTIFF (.tif), or a .zip containing one GeoTIFF, with predictions on the competition grid. It must match the submission format's CRS, shape, and geotransform exactly.

Format specification (from the official template)

  • Bands: 1 (single-band)
  • Dtype: float32
  • CRS: EPSG:32611 (UTM zone 11N, NAD83)
  • Transform: (100.0, 0.0, 243350.0, 0.0, -100.0, 4508550.0) — 100 m pixels, unrotated
  • Shape: 3730 rows × 3292 columns
  • Values: all finite values in [0, 1] — no NaN anywhere (use 0.0 outside the scored footprint)
  • Footprint: 5,167,373 scored pixels; values outside are ignored but must still be in [0,1]

The template grid is sample_submission.tif in the competition data. Every submission is checked against it before scoring.

PORTAL ERROR — "PREDICTED VALUES MUST BE IN RANGE [0, 1]"

Cause and fix

The DrivenData submission form validates that predicted values lie in [0, 1]. A NaN pixel fails this check because NaN >= 0 and NaN <= 1 both evaluate to false. Even though NaN is legitimate for "no data" outside the bounds, a naive validator rejects it.

Fix: write 0.0 outside the footprint instead of NaN. Then np.all((a >= 0) & (a <= 1)) is true for every pixel, and the portal's range check passes. All rasters built by this repo's scripts use zeros outside the footprint.

Before upload, verify with:

python scripts/portal_range_check.py your_submission.tif
# Check: naive_whole_array_pass = true
# Check: nan_count = 0, inf_count = 0
# Check: finite_min >= 0 and finite_max <= 1

UNIQUE NAME AND NOTE

Naming your submission

The submission form asks for:

  • File to submit: the .tif or .zip
  • Note (optional): "A short comment to help you or your team tell submissions apart later e.g. clustering with k=25" — maximum 140 characters

Recommended name format: <team>-<method>-<date>-<hash>-zeros.tif

Recommended note format (≤140 chars): describe the method in one line, e.g. Off-catalogue geothermal-conduit dots: dilatation+curvature+conductivity, >=3px off catalogue + focus halos, 4px NMS, 20k dots (126 chars).

Never reuse a name or note from an already-submitted file. Duplicates are detectable and waste a weekly slot.

STEP-BY-STEP UPLOAD

How to make a submission

01

Confirm the file is cleared

Only an independent selector may pick an eligible candidate. Check the current weekly allowance on the authenticated DrivenData submission page. The rules allow three submissions per week.

02

Download the approved file

Download the single-band GeoTIFF (.tif) or a .zip containing one GeoTIFF. Verify its SHA-256 hash matches the published value. Verify the name is unique and the note is ≤140 characters.

03

Run the format checker

python scripts/validate_geotiff.py your_submission.tif --template .cache/gems_data/sample_submission.tif and python scripts/portal_range_check.py your_submission.tif. All checks must pass.

04

Upload via the official form

Go to DrivenData competition page ↗. Select Submit → Make new submission, choose the .tif/.zip, paste the note, and submit. Retain the file-linked organizer receipt as proof of submission.

05

Record the result

Save the organizer receipt (submission ID, score if available, timestamp). Log the SHA-256, name, note, and holdout DTI in your run card. Do not resubmit the same file.
