How to make a submission into the contest

  1. Get the data (DrivenData login required — verified redirect to login, cannot auto-download here): https://www.drivendata.org/competitions/306/competition-doe-gems/data/. Place training_features.tif, labels.tif, sample_submission.tif into data/.
  2. Prepare the stack: python scripts/prepare_data.py
  3. Generate + align to competition grid:
    python scripts/generate_submission.py
    python scripts/align_to_competition_grid.py --reference data/sample_submission.tif
  4. Write + validate (format receipt):
    python scripts/submission_writer.py --reference data/sample_submission.tif
  5. Run all gates: python scripts/validate_submission.py → verdict promote / negative
  6. Upload via the DrivenData submission page (single .tif or .zip, note ≤140 chars), within the weekly cap.

Fix for "Predicted values must be in range [0, 1]"

The portal rejects values outside [0, 1] or NaN. The pipeline guarantees: np.clip(prediction, 0, 1), replace non-finite with 0 (-zeros encoding), single-band float32, finite everywhere, no NaN inside the footprint. GEMSDOE research pages confirm the same format receipt: "0 NaNs anywhere, float32 in [0,1]".
