A transparent pipeline for the DOE GEMS Prize Challenge

This repo implements the official metric, grid, submission writer and validator for DrivenData competition #306 — finding geologic faults missing from the USGS/INGENIOUS catalogue to accelerate hidden geothermal discovery in the GeoDAWN survey area of NW Nevada — and is honest, in public, about exactly what is and is not yet verified.

Download the one safe, ready-to-upload file in this repo

A format-perfect, all-zero baseline GeoTIFF on the competition's grid. It fixes the previously-reported upload error "Predicted values must be in range [0, 1]" by construction — every pixel is finite and in [0, 1], guaranteed by an automated validator, no human check required. It is not a competitive entry (it predicts no faults at all; true score = 0) — it exists to prove the pipeline works end to end.

Why there isn't a higher-scoring file to download yet

Short version: generating one honestly requires the real competition data (training_features.tif, labels.tif), and this environment has no DrivenData account configured and cannot reach drivendata.org's authenticated data tab, Dropbox, or USGS/OpenEI's binary file hosts from its sandboxed network. We verified this live rather than assuming it — see LIMITATIONS.md for the exact commands and results. Fabricating a "better-looking" raster without real underlying data would be a hallucinated result, which we were explicitly told never to produce. See the executive summary for the full, sourced reasoning and the prioritized plan to close this gap.

What's in this repo

PathWhat it is
src/gems/metric.pyThe official distance-weighted Tversky index, implemented from the published formula and unit-tested against its own worked example.
src/gems/grid.pyThe competition's output grid (EPSG:32611, 100 m, 3730×3292) — official CRS/resolution rule + cross-replicated exact shape/transform (see limitations).

Core values driving this project

Maximize P(Win)

Every decision weighs tradeoffs and risk against what actually raises the probability of a top-of-leaderboard result — not what merely produces the most output.

Own the Outcome

We report blockers and irregularities explicitly rather than hiding them, and we don't wait for permission to fix a shared tool or flag a bad assumption.
