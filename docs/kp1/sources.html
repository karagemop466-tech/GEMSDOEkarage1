External scientific references for the mechanism

  • USGS GeoDAWN airborne magnetic and radiometric surveys, DOI 10.5066/P93LGLVQ (sciencebase item 657e1d85d34e23d3533209f7) — source of the magnetic, radiometric and DEM grids, including the upward-continued and ratio products used here.
  • GBCGE INGENIOUS project — the geothermal-favourability framework and trace database that the catalogue incorporates.
  • EPSG:32611 (UTM 11N) — the required coordinate reference system.
  • Tversky index — the similarity index the distance-weighted metric is built from.

Irregularities flagged for review

  1. labels.tif and existing_faults.tif are byte-identical (7ba308cc…), while the organizer page says a “sample submission that predicts total fault absence” is provided. The sample-submission mirror actually carries 1s, including 60,988 positives equal in count to the catalogue. Treat the mirrors' roles as owner-described, not organizer-authenticated.
  2. The 70 % / 3-px uniqueness rule is saturating for this raster family (all 36 pairs 97.5–100 % against a 15–18 % chance level). It cannot discriminate copying from shared terrain and needs an owner decision.
  3. The shared holdout evaluator anti-correlates with known scores (Spearman −1.0 on the nine), so it cannot gate promotion as currently specified.
  4. The vendor external pins are stale: vendor/gems57/prepare_data.py lists data/external/derived_sgmc_faults_100m.tif, sgmc_faults_100m.tif, trace_segments_utm11.csv and qfault_attributes.csv under repository buffedlizard55-lab/6GEMSDOE@e2fe3f41, but that commit contains no data/external tree, so the fetch fails. The proxy used here has the same SHA-256 as the first of those pins (643cbe99…) and was taken from buffedlizard55-lab/GEMSDOE24; the file is therefore the intended bytes even though its pinned path is dead.
  5. No organizer receipt exists for any score on this site. All nine focus scores are user-reported; the projection is a model output.
