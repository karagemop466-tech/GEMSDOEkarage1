What the estimate means — and what it does not

Every number above is a HOLDOUT-DTI: the official distance-weighted Tversky formula (α = 0.2, β = 0.8, 300 m triangular kernel) scored against withheld whole segments of the public catalogue, with visible segments masked pixel-exactly. It is a screen for choosing between recipes. It is not a leaderboard projection: the live hidden set (expert-mapped faults absent from the catalogue) is not available, and the sibling repositories measured that catalogue-truth holdouts rank live scores across detector families only weakly (Spearman ≈ 0.5, n = 12). The only ORGANIZER-CONFIRMED numbers in this project are the ones a human copies from a DrivenData submission receipt; there are none yet for this file.

Why 0.2778 scored what it did (GEMSDOE32), and what this lane does differently

  1. Metric algebra. With T = kernel-weighted credit, S = emitted mass, M = emitted mass that best-covers truth and |G| hidden-truth pixels: DTI = T / (0.2·(T + S − M) + 0.8·|G|). Every emitted pixel whose realised kernel credit falls below 0.2·DTI lowers the score; binary 0/1 dots on the best-ranked pixels dominate any softened map. (Verified in src/gemsk/metric.py against a brute-force transcription; test tests/test_metric.py.)
  2. The 0.2778 file is a thinning ladder of one field. H19-5 (121,131 px → 0.1922) → dotted at 2.8 px (44,090 → 0.2600) → every dot ≤1 px from the catalogue deleted (40,199 → 0.2708) → ≤2 px deleted (37,654 → 0.2778). All nine focus-site "winners" are members of this one nested family; three are byte-identical rasters (see nine sites). Scores are OWNER-REPORT.
  3. H19-5 is catalogue-trained. Its "Line 1" is the catalogue's own fault traces (tips/step-overs) and its four experts are out-of-fold models fitted on the catalogue (read from 19GEMSDOE/src/gems/hypotheses.py). A catalogue-trained field predicts catalogue-like faults; the hidden expert-mapped strands are physically similar and spatially close to catalogued ones, and the 2-px apron deletes the part that is merely the catalogue itself. That is the mechanism.
  4. Measured here, not assumed: on an interleaved hide-and-recover split, 67% of withheld catalogue strands lie within 1.5 km of a visible strand (26% of the area), with a ≈4× density lift at 300–600 m and <0.25× beyond 4 km (evidence/exp1b_truth_vs_distance_to_visible_interleaved.json). Across the whole sibling portfolio, every "blind basin / far-from-catalogue" design scored ≈0 live (0.0000–0.0009, OWNER-REPORT).
  5. This lane therefore puts a label-free step-edge physics field (not a Hessian ridge), gated by the scarp's facing direction relative to the basin-deepening direction read from gravity and basement depth, inside that measured damage-zone prior. The result overlaps the 0.2778 file by only 24% (3 px) — its median dot sits 540 m from the catalogue versus 1,960 m for the champion. That is the contrarian bet, stated plainly: if the hidden faults cluster like the catalogue's own strands, this gains; if they are predominantly far-field, it loses.

Can we beat 0.2778?

Not provably from here — no local instrument can measure the live hidden set. What is established: (a) on the same evaluator this recipe beats the H19-5 source field re-emitted under the same rule (0.1298 vs 0.1049 interleaved) even though H19-5 was trained on the catalogue pixels it is being tested on; (b) the prior-only arm reaches 0.1131, so the physics contributes +0.0167 — real but secondary, and the page says so; (c) the holdout curve is still rising at 70,000 dots because catalogue truth is dense (≈15k withheld px per fold against ≈45k visible); the live hidden set is believed sparser, so the pre-registered rule took the lower end of the family's live-optimal range (36,000 dots) rather than extrapolating upward.
