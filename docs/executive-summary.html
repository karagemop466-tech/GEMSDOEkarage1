Why did GEMSDOE32 score highest (0.2778), and can we generate something higher?

Mechanism (measured, not a score): GEMSDOE32's B2 file equals the GEMSDOE25 mask with roughly 6,436 dots removed — the dots lying within ~2 px of the mapped catalogue — and none added. Because the organizer masks known catalogue faults from scored truth, dots on/near the catalogue earn little true-positive credit and real false-positive credit. Removing them raises per-dot efficiency, so GEMSDOE32 reaches the highest reported value (0.2778) with the fewest dots (37,654) of the high scorers. It is the catalogue-collar / off-catalogue prune strategy.

Can we beat 0.2778? Not demonstrated here, and no leaderboard estimate can be produced (labels login-walled). Reaching the leaderboard top (0.4413 organizer-public; 0.3195 rank ~#48) requires roughly 1.86× the champion's per-dot accuracy, or independent expert fault traces that are not in the catalogue. Nothing in this checkout has demonstrated either, so no file is promoted and no weekly slot is spent.

The format ceiling is 0.5556; the exact marginal bar on one more dot is alpha·s/(1−s) ≈ 0.0769 at s=0.2778 and ≈ 0.158 at s=0.4413.

New unique submission (lane H-NT · Novel Territory)

Hypothesis: geothermal systems are commonly hosted on blind or partially-mapped faults absent from the USGS/INGENIOUS catalogue. The nine prior submissions all dot the same catalogue corridor, so the complementary, uncatalogued fault set lies outside their 3-px halos ("novel territory"). Dots restricted to novel territory target that missing-fault set and are unique by construction.

Mechanism: DTI = TP / (TP + 0.2 FP + 0.8 FN), 300 m triangular kernel. Catalogue faults are masked from scored truth, so novel-territory dots avoid the false-positive penalty of the catalogue corridor while targeting uncatalogued structures. Binary dots concentrate probability (TP linear in p; FP weighted only 0.2). Pixels are ranked by distance to the nearest prior dot (farther = less redundant) and emitted with 3-px non-maximum separation.

Named non-fault mimic: Pluvial Lake Lahontan shoreline berms, TIGER road/rail embankments and conductive playas can produce linear anomalies in novel territory; mitigated by restricting dots to novel territory and keeping the count small (20,000).

How to make a submission to the contest (once a file is cleared)

  1. Pass the automated gates. Run the shared evaluator (scripts/evaluate_holdout.py), per-feature leakage canaries (AUC must stay below 0.90), and the registry-overlap / uniqueness check against the pinned registry rasters. Beat a frozen comparable holdout best; validate saved TIFF bytes (format, range [0,1], CRS/shape/transform match).
  2. Choose a slot separately. Only an independent selector picks an eligible candidate and checks the current weekly allowance on the authenticated DrivenData submission page (the September rules allow three submissions per week). Generation and slot selection are separate steps.
  3. Download the exact file. Get the approved single-band GeoTIFF (.tif) or a .zip containing one GeoTIFF. Check its displayed SHA-256, unique name (<= implied by filename convention) and note (<= 140 characters).
  4. Upload via the official form. Open DrivenData · DOE GEMS, select Submit → Make new submission, choose the .tif or .zip, paste the note, and retain the organizer receipt (ORGANIZER-CONFIRMED).
