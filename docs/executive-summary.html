SUBMISSION GUIDE

How to make a submission into the contest

These steps apply once a candidate is cleared by the gates. They are not permission to upload either historical artifact.

01 / EVIDENCE

Pass the automated gates

Use the shared evaluator (vendor/gems57/evaluate_holdout.py), fold-local features, and per-feature leakage canaries. Beat a frozen comparable holdout best on a spatially-blocked hide-and-recover holdout. Audit surface and dots against the complete registry (|Spearman| ≤ 0.90 and ≤ 70% of dots within 3 px). Reopen the TIFF and validate saved bytes.

02 / SELECTOR

Choose a slot separately

Only an independent selector may choose an eligible candidate and check the current weekly allowance on the authenticated submission page. The competition rules allow three submissions per week. No slot is selected or spent in this session.

03 / DOWNLOAD

Choose the exact file

Download the approved single-band GeoTIFF (or a ZIP containing one GeoTIFF). Check its displayed SHA-256, unique name (≤ 140 characters), and note (≤ 140 characters). The file must be float32, all values in [0, 1], EPSG:32611, matching the sample submission's shape and geotransform, with no positive mass outside the footprint.

04 / UPLOAD

Use the official form

Open DrivenData GEMS, select Submit → Make new submission, choose the .tif or ZIP, paste the note, and retain the organizer submission-page receipt as ORGANIZER-CONFIRMED evidence.

The official rules require disclosure of generative-AI use in the narrative when applicable. Public leaderboard performance is not the private final score. Values must be in [0, 1] — the earlier "Predicted values must be in range [0, 1]" rejection is fixed by the all-finite export policy used here.
