3. The answer, and what would change it

  1. Holdout: the pre-registered rule needs pooled HOLDOUT-DTI above random placement with a paired CI above zero. H-R1 misses both.
  2. Target mismatch (irregularity): the internal holdout's truth is mapped USGS/INGENIOUS segments. The competition scores against new faults that are not in the USGS database (official problem page ↗). The holdout therefore rewards a different target. A holdout gain is still a screen, not a leaderboard estimate.
  3. Next candidate: H-E1, Euler deconvolution with depth clustering. The repo has no Euler code (verified by grep, 30 Oct 2026). It is ranked second in knowledge/hypotheses-20261030.md and is not yet tested.

4. Irregularities flagged for review

  1. The user-reported 0.4413 does not appear in the official top 50 on 30 Oct 2026. The repo's earlier note placed 0.3195 at #47; this snapshot shows #48 (#47 = 0.3217). Official leaderboard ↗ · registry/leaderboard_snapshot_20261030.json
  2. Format conflict: the official text says data outside the bounds is "null or nan". The shared writer accepts all-finite zeros only, and labels NaN as diagnostic. Both files are provided. The cause of the portal error "Predicted values must be in range [0, 1]" is not established by any local test.
  3. Holdout target mismatch (section 3): the evaluator's truth is the mapped catalogue, and the competition's test set is not.
  4. The 70% / 3 px lattice rule is an internal protocol rule, not in the official problem page. It fails on dense rasters regardless of copying (section 2).
  5. GeoDAWN radiometrics come from the USGS data release doi:10.5066/P93LGLVQ (verified on the USGS page ↗, CC0). The uint8 K/Th/U/TC grids used here are an owner-derived mirror. They are not organizer-authenticated, and the quantisation is not independently checked.
  6. The vendored grid loader hard-codes data/bridge. The earlier data test failed for that reason. The fix here is a git-ignored symlink, not a template change, because vendor/PROVENANCE.json pins file hashes. A template fix needs an owner decision.
  7. The home page strip pointed at an older file (hgridge, 29 Oct). It now points at this session's page.
