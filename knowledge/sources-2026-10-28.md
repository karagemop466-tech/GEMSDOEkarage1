## Restored mirrors and reproducibility

The [manifest](../registry/karage1_data_manifest.json) pins each source to an
immutable GitHub commit plus a SHA-256 and byte length. The [verification
receipt](../evidence/data_restore_verification_20261028.json) records 31 files
(4 core, 12 external, 15 scored; 551,538,109 bytes) restored and rechecked in
`.cache/gems_data`, which is excluded from Git and snapshots. Matching a
third-party GitHub hash establishes byte identity with that pin only, not source
authenticity, current licensing, completeness, or organizer acceptance.

The mirrored `sample_submission.tif` has 60,988 positive pixels and its binary
mask equals the mirrored `labels.tif`. The official page describes the sample
as predicting total fault absence. Until the organizer's sample is obtained and
cross-checked, the mirror must be treated as a **grid/footprint only**, never as
a clean prediction or feature. See [reference audit](../docs/data/reference-audit.json).

Historical prerequisites that remain absent or unresolved: the assigned lane,
the authoritative shared template family, prepared shared feature cache,
complete registry inventory, independent current-best same-evaluator holdout,
and organizer-authenticated submission-template bytes. Neither restored data
nor a read-only hash check constitutes a geological experiment.
